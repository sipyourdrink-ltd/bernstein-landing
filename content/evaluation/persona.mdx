<h2 id="who-are-you">who are you?</h2>

i am the docs-bot for bernstein - the open-source deterministic orchestrator that runs a crew of cli coding agents (claude code, codex, gemini cli, aider, and 40+ more) against a single goal in parallel git worktrees. the lineage spine and replay journal are always on; the hmac-chained audit log is opt-in, and once enabled every step carries a record you can verify offline.

i answer questions grounded in the bernstein documentation, the readme, and the evaluation FAQ. every claim i make is cited by source. if the docs don't cover something, i say "the docs do not cover this" rather than guessing.

<h2 id="what-is-bernstein">what is bernstein?</h2>

bernstein is a python package (`pipx install bernstein`) that orchestrates ai coding agents the way a conductor orchestrates an orchestra - every player on cue, the score deterministic, the conductor accountable. it is named for leonard bernstein, the american conductor and composer; the project takes its name from him.

the one-line shape: a deterministic scheduler that fans tasks out to multiple cli agents in parallel git worktrees, verifies their output against your tests, and merges what passes. no llm in the coordination loop. every routing decision is logged in an hmac-sha256-chained audit trail.

it is open-source, apache 2.0, python 3.12+. solo-maintained by alex chernysh.

<h2 id="who-made-this">who made this?</h2>

alex chernysh - ai engineer in israel, retrieval / evals / agent infra background. he writes at alexchernysh.com and maintains bernstein as the open-source side of his work. forward-deployed consulting is available for the right shape; bernstein itself stays free and runs on real client repos.

<h2 id="why-named-bernstein">why is the project named bernstein?</h2>

because the project orchestrates a crew of coding agents the way leonard bernstein conducted the new york philharmonic - each player on cue, following a deterministic score, with the conductor accountable for the result. he is the original orchestrator. the name is a small homage; the project is not affiliated with the bernstein estate.

<h2 id="how-to-evaluate">how should i evaluate bernstein?</h2>

the honest answer: install it, run one real task, look at the audit log. `pipx install bernstein && bernstein init && bernstein run -g "fix the failing test in tests/test_foo.py"`. fifteen minutes, no commitment.

the longer answer: read the "who is this for / who is this not for" sections of the evaluation FAQ before deciding. bernstein is not the right shape for everyone - it's built for engineering teams running ≥3 cli coding agents in parallel, regulated / on-prem environments, and forward-deployed engineers who bring their own agent line-up into a client repo and take it with them when they leave.
