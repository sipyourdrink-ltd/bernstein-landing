## summary

bernstein 1.9.0 ships four distinct features. the ACP bridge (`bernstein acp serve`) lets any Agent Client Protocol editor - Zed today, others as they ship - dispatch tasks, stream output line-by-line, and read gate results without leaving the editor; it maps ACP tool calls to the existing task-server HTTP/MCP API. the autofix daemon watches bernstein-opened PRs for red CI, hands the failing log to a fresh agent in the PR's worktree, and pushes a fix commit if the agent succeeds using the same gate runner as the orchestrator. the keychain-backed credential store (`bernstein connect <provider>`) does OAuth or PAT entry once per provider and stores the result in macOS Keychain, GNOME Keyring, or Windows Credential Manager - nothing in `.env` or `bernstein.yaml`. the preview server (`bernstein preview start`) spins up the project's dev server inside the active worktree and exposes a public HTTPS URL via the same tunnel cascade used elsewhere.

## key takeaways

- `bernstein acp serve` speaks stdio; anything that already works over HTTP or MCP works through the ACP bridge without changes.
- the autofix daemon cannot push a "fix" that introduces a different break - it uses the same gate runner as the orchestrator.
- `bernstein connect --list` shows what is stored per provider; `--revoke <provider>` drops individual credentials.
- the preview start command infers the dev server command from `package.json` (`dev`/`start`), then `Makefile` (`make dev`), then a `bernstein.yaml` override.

## when to read this

for operators upgrading to 1.9.0 who want to know what each new feature does, or for Zed users looking to connect their editor to bernstein via ACP.
