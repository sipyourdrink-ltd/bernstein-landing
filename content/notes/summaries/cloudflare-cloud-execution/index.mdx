## summary

bernstein's experimental Cloudflare integration moves agent work off the local machine while the orchestrator stays local and deterministic. agent runs go to Workers (cold start under 50ms), multi-step tasks with ordering and retry land on Workflows, workspaces sync through R2, and usage metering goes to D1. `bernstein cloud init` scaffolds a `wrangler.toml` and a worker entry point; you deploy with `npx wrangler deploy` against your own Cloudflare account. the hosted commands (`cloud login`, `run`, `status`, `runs`, `cost`) target `api.bernstein.run`, which does not resolve in DNS, so they report the service unreachable.

## key takeaways

- Workers bill per request, not per VM; for a typical 50-task session, compute cost is roughly $0.50-2.00, while R2 and D1 are pennies.
- Workflows resume from the last completed step, so a Worker crash mid-task does not restart the task from scratch.
- API keys are stored as Worker secrets via `npx wrangler secret put` and never leave Cloudflare.
- the orchestrator and its `.sdd/` state stay local; D1 is the metering ledger, not the source of truth.

## when to read this

for teams hitting concurrency or thermal limits on a local machine, or needing agent sessions that survive network disconnects and laptop lid-closes.
