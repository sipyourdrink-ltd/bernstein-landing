## summary

bernstein 1.8.4 adds a Cloudflare backend that moves agent execution off the local machine. stateless agent runs go to Workers (cold start under 50ms), multi-step tasks with ordering and retry land on Durable Workflows, diffs and generated files go to R2, and task queue plus audit log go to D1. the local `.sdd/` story stays intact for development; the cloud backend is for when running four or five concurrent agents on a MacBook starts causing thermal problems or you need sessions that survive a lid close. `bernstein cloud deploy` creates the full topology in one command; `bernstein run --cloud` dispatches tasks against it.

## key takeaways

- Workers bill per request, not per VM; for a typical 50-task session, compute cost is roughly $0.50-2.00, while R2 and D1 are pennies.
- a Durable Object holds orchestrator tick state so a Worker crash mid-task resumes from the last completed step rather than from scratch.
- API keys are stored as Worker secrets via `wrangler secret put` and never leave Cloudflare.
- the Cloudflare backend replaces local `.sdd/` state for cloud runs; multiple Workers can read D1 without stepping on each other.

## when to read this

for teams hitting concurrency or thermal limits on a local machine, or needing agent sessions that survive network disconnects and laptop lid-closes.
