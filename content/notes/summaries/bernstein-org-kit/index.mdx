## summary

`bernstein-org-kit` 0.2.0 (`org-kit-v0.2.0`) is an Apache-2.0 plugin in `sipyourdrink-ltd/bernstein-addons` that scaffolds governed multi-agent workspaces on top of Bernstein. `bernstein-org-kit init` offers 6 presets: `minimal` by default (6 roles, 3 workflows, compiling 7 roles and 7 principals including `owner`), four domain presets (`secops`, `product`, `compliance`, `engineering`), and `--preset full` (36 roles, 16 SOPs, 20 workflows, 32 scenarios, 9 authoring templates, 6 starter tasks, compiling 37 roles and 37 principals). JSON DAG workflows compile deterministically without a model via `bernstein-org-kit workflows compile`, `bernstein-role-pack` 0.1.0 enforces independent SHA-256 acceptance (`SelfReview` and `HashMismatch` refused), and `bernstein-org-kit run` defaults to dry-run preview while gating eight human approval categories until explicitly passed with `--approve-gate`.

## key takeaways

- packages in `bernstein-addons` are installed from tagged git URLs (`role-pack-v0.1.0` and `org-kit-v0.2.0`) alongside `bernstein>=4.0.1,<5`, as they are not currently on PyPI.
- compiling `.sdd/role-pack/roles.toml` checks that every reporting line reaches `owner` with no cycles or missing managers; `org/ORG.md` states a cap of seven direct reports per manager as a written rule.
- `bernstein-org-kit demo` runs offline in a temporary directory with no model, API keys, or network access to verify `SelfReview`, `HashMismatch`, exact SHA-256 acceptance, and `code-review-merge` DAG progression.
- documented limits: principals are caller-supplied names, `ledger.jsonl` is a plain file on disk, hooks fire only for HTTP task routes under `bernstein trust --workdir DIR`, and `role_pack_acceptance` is configured via Python `QualityGatesConfig` rather than `bernstein.yaml`.
