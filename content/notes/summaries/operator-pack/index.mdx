## summary

every team running bernstein daily ends up with a `scripts/` directory full of wrappers: a `post-run.sh` that opens a PR with a hand-rolled summary, a one-liner that reads a Linear webhook, an `ssh-run.sh` that rsyncs to a build box, a pre-commit hook that checks gate results. bernstein 1.8.14 replaces those four patterns with first-class commands. `bernstein pr` reads `.sdd/sessions/<id>-wrapup.json` and opens a GitHub PR with a conventional-commit title and a body that includes the diff summary, quality gate results (lint, types, tests, security), and a cost breakdown. `bernstein from-ticket <url>` pulls a Linear, GitHub Issue, or Jira Cloud ticket and maps its labels to bernstein role and scope. `bernstein remote` wraps SSH access with ControlMaster reuse (per-call overhead drops from ~500ms to ~30ms). `bernstein hooks` provides six lifecycle events (`pre_task`, `post_task`, `pre_merge`, `post_merge`, `pre_spawn`, `post_spawn`) with whitelisted env inheritance.

## key takeaways

- `bernstein pr` attaches verified gate results and exact cost ($0.38 · 182,410 tokens in the example) to each PR body automatically.
- `bernstein from-ticket` supports Linear (GraphQL), GitHub Issues (gh CLI or REST), and Jira Cloud (REST v3); labels drive role and scope mapping.
- SSH ControlMaster reuse in `bernstein remote` drops per-command overhead from ~500ms to ~30ms.
- shell hooks receive a JSON payload on stdin plus four env vars; a non-zero exit from any `pre_*` hook aborts the event - useful for "don't spawn if working tree is dirty."

## when to read this

for teams who want to close the loop from ticket to PR to Slack notification without a `scripts/` directory full of one-off wrappers.
