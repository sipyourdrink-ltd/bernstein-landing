## summary

bernstein 1.0 is an open-source orchestrator for CLI coding agents - Claude Code, Codex, Gemini CLI, and anything else that talks over a terminal. the project started after a 47-hour weekend run with twelve parallel Claude Code sessions that produced merge conflicts instead of a working codebase. the solution is a plain-Python tick-based scheduler with no LLM in the scheduling loop, a git worktree per agent so they never share file paths during execution, and a merge queue that lands what passes quality gates and rolls back what doesn't. state lives in `.sdd/` as YAML and JSON with no database required. agents are short-lived (one to three tasks each) to avoid token rot.

## key takeaways

- no LLM in the scheduling loop - the orchestrator is a plain state machine; only the goal decomposition step calls a model.
- 18 adapters at launch (Claude Code, Codex, Gemini CLI, OpenAI Agents SDK, Aider, Cursor, Amp, Kiro, Kilo, Qwen, Goose, and more); new adapters are roughly 100 lines of Python.
- state in `.sdd/` files means `cat`, `grep`, and `git` all work on orchestrator state - no Redis, no database.
- 1.0 ships: tick-based orchestrator, task store with retry and dead-letter queue, quality gates, cost tracking, HMAC-signed audit log, task server on port 8052, and a TUI.

## when to read this

for developers evaluating bernstein before a first run, or anyone who wants to understand the core design decisions - worktree isolation, deterministic scheduling, file-based state - and why they were made.
