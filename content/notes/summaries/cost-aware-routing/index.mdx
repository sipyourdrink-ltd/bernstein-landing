## summary

most agent frameworks send every task to the same model regardless of complexity - routing a docstring task to Opus instead of Haiku is roughly 30x overspend at current pricing. bernstein's cost-aware router uses three layers: a heuristic classifier that maps task `complexity` (low/medium/high) and `role` (backend, qa, security, docs, etc.) to an opening model guess; an epsilon-greedy bandit that exploits the best-known model 80% of the time and explores 20%; and cold-start effectiveness data seeded from `.sdd/metrics/`. across bernstein's own self-development sessions, bandit routing cut the bill roughly in half versus Sonnet-for-everything, with completion rate staying within a couple of percent. a 10-agent / 50-task session that used to run $15-20 lands at $7-10.

## key takeaways

- routing docstrings or test writing to Haiku or Sonnet while reserving Opus for architecture and security tasks is the dominant learned pattern.
- bandit epsilon is 0.2 by default (configurable); the cascade ordering is cheapest-to-strongest - high-complexity tasks never get sent to Haiku.
- rewards are measured as: task completed, tests green, no retries - not a proxy metric.
- bandit is default-on once `.sdd/metrics/` exists; disable with `bandit_enabled: false` in `.sdd/config.yaml`.

## when to read this

for operators trying to reduce per-session LLM spend without sacrificing completion rate, or for teams wanting to understand how bernstein selects models across a multi-agent run.
