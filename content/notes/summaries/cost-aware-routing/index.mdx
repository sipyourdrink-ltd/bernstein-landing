## summary

most agent frameworks send every task to the same model regardless of complexity - routing a docstring task to Opus instead of Haiku is roughly 5x overspend at current pricing. bernstein's default router is a static cascade that starts each task at the cheapest viable tier (`sonnet` then `opus`) and escalates on failure. an opt-in LinUCB contextual bandit (`BERNSTEIN_ROUTING=bandit`) learns the model per task from a feature vector, a separate UCB1 bandit learns the effort level, and capability floors keep high-stakes work from dropping below Sonnet. policy state persists under `.sdd/routing/`. across bernstein's own self-development sessions in April 2026, on the since-retired epsilon-greedy router, bandit routing cut the bill roughly in half versus Sonnet-for-everything, with completion rate staying within a couple of percent. a 10-agent / 50-task session that used to run $15-20 landed at $7-10.

## key takeaways

- routing docstrings, test writing and bug fixes to Sonnet while reserving Opus for architecture and security tasks is the typical pattern after warm-up.
- the static cascade is the default; `BERNSTEIN_ROUTING=bandit` turns the bandit on, and `bandit-shadow` only logs what it would have picked.
- reward is `quality_score * (1 - normalized_cost)`; quality is 1.0 when janitor verification passes, 0.0 when it fails.
- policy state lives in `.sdd/routing/policy.json` and `.sdd/routing/bandit_state.json`; delete the directory and the router starts cold.

## when to read this

for operators trying to reduce per-session LLM spend without sacrificing completion rate, or for teams wanting to understand how bernstein selects models across a multi-agent run.
