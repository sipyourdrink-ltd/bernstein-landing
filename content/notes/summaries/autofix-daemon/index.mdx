## summary

with operator-supplied polling and dispatch hooks, the autofix daemon polls every `poll_interval_seconds` (default 60s) for Bernstein-opened PRs with a red CI run. the dispatcher truncates the supplied failing log to 64KB, runs it through a keyword classifier that buckets the failure as `security`, `flaky`, or `config` (unmatched logs fall back to `config`), and hands the truncated log to a fresh agent in the PR's worktree. if the agent succeeds, a fix commit is pushed on top of the branch; if it fails three times (`MAX_ATTEMPTS_PER_PUSH = 3`), the PR is labelled `needs-human` and the daemon stops touching it. five non-optional safety rails - a per-PR opt-in label, a per-repo per-attempt cost cap (default $5), a hard attempt limit, force-push off by default, and an HMAC-chained audit log - keep the loop from becoming a runaway.

## key takeaways

- PRs must carry the `bernstein-autofix` label to be visible to the daemon; it is checked before an attempt starts, and removing it does not cancel an attempt already running.
- per-attempt cost cap (`cost_cap_usd`, default $5) checks reported spend after dispatch and records an exceeded cap.
- after three failed attempts against the same commit SHA, the daemon posts a summary comment and labels the PR `needs-human` - no retry-forever path exists.
- `FailingPRSource` and `DispatchHook` are protocols; the CLI ships the rails-and-state half, and operators can inject custom hooks via the Python API today.
- every attempt start and end is appended to `.sdd/audit/` in an HMAC-chained JSONL that detects tampering and enables full reconstruction after the fact.

## when to read this

for operators who want to automate repair of lint, type-check, and import errors on Bernstein-opened PRs without writing a custom CI bot or risking an unbounded retry loop.
