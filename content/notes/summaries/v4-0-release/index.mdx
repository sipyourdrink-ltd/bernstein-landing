## summary

Bernstein 4.0.0 (Apache-2.0) focuses on conditions that previously passed quietly. A failed workflow node now stops every later layer including independent branches instead of letting them dispatch and write success checkpoints, and a detached SSH task exiting nonzero now fails the run instead of recording completion. `bernstein govern audit --strict` exits 1 when a check fails or crashes and 2 when a check could not be measured or on a usage error. Normal run closure seals the final delegation digest with an HMAC under the install audit key so a deleted tail fails verification, while noting that replaying an earlier authentic snapshot does not. Three first-time contributors joined this release, and operators are advised to install or upgrade from `releases/latest` (4.0.1, 4.0.2, and later) rather than pinning 4.0.0.

## key takeaways

- install or upgrade via `pipx install bernstein`, `pipx upgrade bernstein`, or `uv tool install bernstein` from `releases/latest` so patch releases (`4.0.1`, `4.0.2`, and later) are included.
- failed workflow nodes halt all later layers (including independent branches), and nonzero detached SSH exits fail the run.
- `bernstein govern audit --strict` returns exit 1 on failed/crashed checks and exit 2 on unmeasurable checks or usage errors.
- HMAC sealing on normal run closure detects deleted delegation-chain tails, while replaying an earlier authentic snapshot remains an explicitly documented limitation in the 4.0.0 release notes.
