## summary

the 2.x line taught the orchestrator to do more; the 3.x line made each capability carry its own proof. every run folds into a single Ed25519-signed lineage spine, deterministic replay is on by default (the step journal is a Merkle chain, so drift is a hash divergence at a named step), and "done" became a content-addressed evidence bundle sealed into the audit chain instead of a status line. the durable work ledger makes runs survivable — resume on another machine with zero lost work, or detach a run entirely with `bernstein run-service` — and scheduling grew receipted, model-free decisions: tournament selection recomputable offline, cost dispatch under USD caps pinned by hash, spec-to-graph compilation as a pure transformation.

## key takeaways

- deterministic replay by default: `bernstein replay --from-step N` rebuilds state from the Merkle-chained step journal; non-determinism surfaces as a hash divergence at an exact position.
- evidence bundles gate completion with declared producers (tests, coverage, lint); deterministic producers replay to byte-identical bundle hashes, and PR bodies link the sealed bundle.
- `bernstein ledger resume` and the detached run service make runs survive interrupts, crashes, and machine swaps; provider failover is a receipted decision you can rehearse with `bernstein doctor --failover-drill`.
- tournament runs pick winners as a pure function of scripted evaluator outputs — no model in the decision path; `bernstein tournament verify` recomputes the selection offline.
- the operator surfaces caught up: scoped dashboard tokens, a deterministic run review board with diff and evidence panels, SPIFFE-compatible identity, an experimental MCP Tasks surface, and a stateless chain-anchored MCP core.
- windows went from one silent-exit fix to a tested lane: adapter conformance for claude, codex, and gemini runs on a real windows runner.

## honest framing

none of this has been through an external regulatory audit: treat the chain, the bundles, and the standalone `bernstein-verify` wheel as verifiable artefacts an evaluator can recompute, not as an attestation someone has already signed off.
