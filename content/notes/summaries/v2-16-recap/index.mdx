## summary

Twelve point releases from 2.4 through 2.16 (plus the 2.16.1 Windows fix) focus on three areas. The output-economy suite introduces run-level `--max-cost-usd` budgets, line-item attribution in `bernstein cost` (and `bernstein cost --by profile`), and Brier-scored pre-step spend forecasts based on adapter-reported usage. Deterministic, auditable orchestration closes prior HMAC audit-chain gaps, verifies hash-identical task graphs across matching inputs, and pairs `bernstein compliance pack` with the standalone `bernstein-verify` wheel (`cryptography` and `click` only, asserting `import bernstein` raises `ModuleNotFoundError`). Finally, 2.16.1 fixes Windows `.cmd` and `.bat` adapter shims by resolving absolute binary paths before spawning, routing shims through the command interpreter, and passing `PATHEXT` through the worker environment.

## key takeaways

- `--max-cost-usd` caps reported spend per run; `bernstein cost` and `bernstein cost --by profile` attribute charges to task, step, adapter, and model; pre-step forecasts are Brier-scored against actuals.
- two runs with the same seed, plan, and state are compared by hash, and HMAC audit-chain coverage gaps across state transitions and merges are closed.
- `bernstein-verify` checks signed `bernstein compliance pack` bundles independently of `bernstein` (verifiable artefact, not an external regulatory audit).
- upgrading with `pipx install --upgrade bernstein` (or `pip install --upgrade bernstein`) keeps existing 2.x configs and plans (`bernstein run`, `bernstein conduct`, `bernstein live`, `bernstein gui serve`) unchanged while fixing Windows `.cmd`/`.bat` shims.

for operators running 2.x plans who want run-level cost attribution, end-to-end audit chain verification, or reliable Windows adapter execution for npm-installed CLIs.
